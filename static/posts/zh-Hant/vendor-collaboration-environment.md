## 工程挑戰

外部開發者需要存取程式碼儲存庫、測試服務與部署流程。若共用內部開發資源時沒有明確邊界，可能造成資料曝露、環境互相干擾，也會增加檢視存取權限或變更內容的難度。

這項工作從盤點 GitHub 儲存庫、CI/CD、DNS、服務端點、IAM 與 GCP 基礎設施開始，目標是設計可重複使用的協作流程，並為開發者劃分各自的環境範圍。

## 架構與設計

- 為每位外部開發者配置權限範圍獨立的執行環境與服務端點。
- 使用可重用的 Runtime Template 定義服務端點、DNS、TLS 與健康檢查。
- 透過 GitHub Team 或外部協作者權限、分支保護、必要檢查與部署限制，界定原始碼存取範圍。
- 限縮 PostgreSQL、Redis 與 GCS 測試資料的存取範圍。
- 將 GCP IAM、IAP、IP 白名單與防火牆控管納入存取模型。
- 將日誌、監控、敏感資料遮罩與存取稽核列為營運需求。

預期的工作流程會串接儲存庫存取、部署檢查與開發者執行環境。網路與 IAM 規則界定存取邊界，可觀測性與稽核控管則支援後續檢視。這些是設計目標，並不代表所有元件都已部署。

## 實作內容

- 盤點現有 CI、GitHub、DNS、部署設定、IAM 與 GCP 資源。
